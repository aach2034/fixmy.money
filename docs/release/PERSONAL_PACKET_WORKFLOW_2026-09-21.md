# Personal packet workflow — local, non-billing implementation

Status: `OWNER_AUTHORIZED_COUNSEL_REVIEW_PENDING`. This branch is for local review. It does not authorize or perform a production migration, deployment, signup, customer email, invoice, charge, or checkout.

The workflow is default-off. A local test operator can set `PERSONAL_PACKET_WORKFLOW_ENABLED=true` only in an isolated environment after applying the review migrations there. An active platform administrator with MFA and recent step-up invokes `POST /api/admin/personal-packets/{cycleId}/generate` with a saved, consumer-owned `reportId`. The route accepts no customer report content in the request. It requires a completed 30-day cycle after cancellation, a saved readable structured report received during that cycle, no parser error warnings, and the consumer as the report owner. It rejects staff-client reports.

The source-intake follow-up adds a third migration with a consumer-owned commit uniqueness index. During an already active unbilled cycle in that isolated environment, the consumer can paste report text at `/my-packets`, which calls `POST /api/personal-packets/{cycleId}/source`. The route is same-origin, authenticated, owner-bound, size-limited, and default-off. It accepts only a high-confidence successful parse, saves structured fields with `client_id` null and `status=saved`, and returns the report ID for later admin review. Identical submissions are idempotent. It does not create or activate a service cycle, retain raw text, send mail, or complete a packet. Parser diagnostics no longer print candidate report excerpts to console. No production consumer can use this path until an independently authorized rollout.

Generation produces five private UTF-8 text artifacts: a normalized source snapshot, findings, action plan, either consumer-directed dispute drafts or an explicit no-supported-dispute conclusion, and the combined packet. Source facts are labelled as supplied, cross-bureau differences as unverified review prompts, and inferences separately. A dispute draft needs a consumer-confirmed fact referencing this report/account and a linked, accessible tenant-owned supporting document. Otherwise the no-dispute conclusion is used. Nothing mails or submits a dispute. The text packet format is intentionally simple and inspectable; counsel and product review should decide whether a later accessible PDF presentation is needed.

Each artifact is uploaded without overwrite to `personal-review-packets/{consumerId}/{cycleId}/` and downloaded for SHA-256 verification. A retry can reuse an existing object only if the bytes match. The final packet is downloaded again before completion. A single database transaction locks the cycle, records only a neutral in-app notification event and an immutable completion event, and moves it to `completed_unbilled`. A retry returns the same result without another notification. The final evidence records structured-source ID/hash, receipt/processing metadata, engine/ruleset versions, four artifact IDs/hashes, delivery verification, agreement/disclosure versions, cancellation timing, and event IDs. Raw report content is not put in ordinary logs or audit metadata.

Consumers can open `/my-packets` and download their own packet through the authenticated `/api/personal-packets/{cycleId}` route. It checks ownership, cycle-scoped storage path, stored bytes/hash, and records access before returning a 60-second signed download URL. The page and route do not check paid entitlement, so historical access survives any future nonpayment suspension. Direct browser Storage access remains denied.

Suspension cannot arise under this branch because database invoice activation and `invoice_eligible` remain hard-blocked. The local capability decision still requires an actually open, overdue completed-service invoice past grace; absent cycles and legacy customers remain unaffected. New Personal AI analysis, report import/parsing, and dispute generation consult that decision; packet history, privacy/export/deletion, agreements, disclosures, billing disputes, and support are not gated. There is no payment restoration or outbound email adapter. Any future billing release requires counsel-approved contracts, disclosure/cancellation terms, state scope, Stripe and tax review, a separate explicit production authorization, and a new migration replacing the billing hold.

Rollback before any application: do not merge/deploy this branch. After an authorized non-production application, disable `PERSONAL_PACKET_WORKFLOW_ENABLED`; do not drop completed packet or audit data. A later retention-aware rollback would need separate review.
