# September 30 launch rollback and incident procedure

## Known rollback point

- Hosting: ChatGPT Sites production version 204.
- Source: `2654b5833764196130a832a05fd1a133dfd3312d`.
- Database: the release candidate includes FMM-002 raw-report cleanup and the additive
  `certified_mailings` migration. FMM-002 intentionally deletes prohibited raw-report
  material and is not reversible from application code.
- Prerequisite: do not apply either migration until a current recoverable database
  backup has been identified and restored successfully into an isolated target. A
  database restore does not restore Supabase Storage objects; preserve and verify the
  private-bucket recovery path separately.

## Stop rule

Checkout and Personal billing remain held. If signup, authentication, entitlement,
core dispute/letter flow, or tenant isolation fails, keep those holds in place and
restore Sites v204. Preserve logs and do not retry deployment until the cause is
reproduced and fixed locally.

## Incident paths

| Incident | Immediate containment | Recovery check |
|---|---|---|
| Authentication outage | Close signup; leave data untouched; restore v204 if the release caused it. | Existing login, recovery callback, session persistence, logout, and admin AAL2. |
| Payment/webhook failure | Close signup and checkout; do not alter subscriptions, issue charges, or replay uncertain events manually. | Stripe endpoint delivery, webhook signature/idempotency, entitlement reconciliation, failed-payment behavior. |
| Database issue | Close mutation paths; do not rewrite migration history. Restore the verified pre-migration backup only through the documented recovery procedure. Do not expect application rollback to recreate deleted raw-report material. | Project health, restored backup timestamp, schema/migration comparison, tenant tests, and private-object availability. |
| Letter-generation failure | Disable/contain the generation route or restore v204; preserve drafts and audit evidence. | Bureau-specific facts, provenance, human-review warning, preview/save/return journey. |
| Cross-tenant concern | Close signup and affected protected routes immediately; preserve audit logs; treat as a security incident. | Reproduce with synthetic tenants; verify RLS, server authorization, storage boundary, and revocation before reopening. |
| Hosting/DNS failure | Check Sites version/domain/TLS health; restore v204. Do not change DNS provider without owner approval. | `fixmy.money`, `www.fixmy.money`, TLS, health endpoint, callbacks, redirects. |

## Post-rollback smoke

Verify `/`, `/login`, `/signup` (closed), `/forgot-password`, `/pricing`, `/security`, `/api/health`, and an existing synthetic customer session. Confirm monitoring receives health/error signals and that no customer communication was sent.
