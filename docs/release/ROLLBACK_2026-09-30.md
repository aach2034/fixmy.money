# September 30 launch rollback and incident procedure

## Known rollback point

- Hosting: ChatGPT Sites production version 196.
- Source: `10e15c0566edf6953b935e250fb299f6cc168d35`.
- Database: this release includes no Supabase migration, so application rollback does not require schema reversal.

## Stop rule

If signup, authentication, checkout, entitlement, core dispute/letter flow, or tenant isolation fails, immediately set `PUBLIC_SIGNUP_ENABLED=false` (or restore the pre-launch environment state), then restore Sites v196. Preserve logs and do not retry deployment until the cause is reproduced and fixed locally.

## Incident paths

| Incident | Immediate containment | Recovery check |
|---|---|---|
| Authentication outage | Close signup; leave data untouched; restore v196 if the release caused it. | Existing login, recovery callback, session persistence, logout, and admin AAL2. |
| Payment/webhook failure | Close signup and checkout; do not alter subscriptions, issue charges, or replay uncertain events manually. | Stripe endpoint delivery, webhook signature/idempotency, entitlement reconciliation, failed-payment behavior. |
| Database issue | Close mutation paths; do not run cleanup or rewrite migration history. No release migration is expected. | Project health, latest recoverable backup, schema/migration comparison, tenant tests. |
| Letter-generation failure | Disable/contain the generation route or restore v196; preserve drafts and audit evidence. | Bureau-specific facts, provenance, human-review warning, preview/save/return journey. |
| Cross-tenant concern | Close signup and affected protected routes immediately; preserve audit logs; treat as a security incident. | Reproduce with synthetic tenants; verify RLS, server authorization, storage boundary, and revocation before reopening. |
| Hosting/DNS failure | Check Sites version/domain/TLS health; restore v196. Do not change DNS provider without owner approval. | `fixmy.money`, `www.fixmy.money`, TLS, health endpoint, callbacks, redirects. |

## Post-rollback smoke

Verify `/`, `/login`, `/signup` (closed), `/forgot-password`, `/pricing`, `/security`, `/api/health`, and an existing synthetic customer session. Confirm monitoring receives health/error signals and that no customer communication was sent.
